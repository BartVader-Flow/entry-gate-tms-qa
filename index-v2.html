Four pillars of the test strategy

7 / 13

Golden data first — then unit, API, and Playwright on the same base. Detail pages link from the Confluence strategy hub.

Four pillars = how we test
Pillar 1 · build first Golden data set

Provisioner-agnostic data for SD-TEST and acceptance. Dev unit tests and QA Playwright share the same IDs — no ad-hoc data.

Owner: TO · Core QA · SA · QA validates at Entry Gate
Pillar 2 Unit testing

Developer loop before handover. SA on volatile packages; root-cause fixes — not patched over in Playwright.

Owner: Dev · SA · QA verifies at Entry Gate
Pillar 3 API testing

Business logic at scale via API — faster and stabler than UI. Playwright only where the UI must prove it.

Owner: Dev · SA · QA consults on risk hotspots
Pillar 4 Playwright automation

Built on golden data; input → expected output like a procedure. Baseline first, then improve in cycles.

Owner: QA · BA consulted · Squad or Core executes

Single entry point

Strategy hub (Confluence) — links deployment, sprint cadence, Entry Gate checklist, Playwright methodology, golden data. One place to start when docs are scattered.

  • Q3–Q4 stepping stone — updated as process matures
  • QA leads maintain links when sub-docs change
  • Flag gaps to Bart / Pablo if story diverges
Deterministic = repeatable feedback loop · not one-off firefighting Rail-Flow · QA

Transition — two tracks in parallel

8 / 13

We cannot change the world in one day. Current release keeps legacy steps; we improve the next cycle incrementally — no big bang.

Track A · now

Current release cycle

  • Follow existing release & feasibility process (e.g. upcoming July release)
  • SaaS / legacy paths where still required
  • Prepare environments as today — expect friction during cutover
  • QA still applies Entry Gate where team is ready
⇄ Parallel
not either/or
Track B · next cycles

New framework (incremental)

  • Golden data first · then Playwright on same base
  • Dev alignment meetings · unit tests before handover
  • Entry Gate + hard reject becomes normal practice
  • Early wins on CargoBeamer & RCG — reuse on other modules
Priority modules: CargoBeamer & RCG first — seeing is believing for stakeholders. Even partial framework use in Track A can save ~30% effort this cycle.

The Entry Gate

9 / 13
Rule: Lifecycle step 2 (Test) starts only after the Entry Gate passes — every item below must be complete before QA picks up the story.

Shared reference for BA · PO · Dev · QA — what we check at handover from Change

Entry Gate checklist

BA and PO deliver · QA validates · hard reject if any item is missing
Deliver: BA / PO
Validate: QA
Story & product
✓ Jira story in sprint & linked epic
✓ Planned fix / release version on story
✓ Acceptance criteria complete & testable (clear pass / fail)
✓ Spec / concept page linked
✓ Story in / out of scope stated (BA / PO)
Test context
✓ Impacted modules & dependencies
✓ App / page / module · provisioner & role for test
✓ BA happy-path: full path + areas that must still work
✓ Test data: Golden Dataset reference or concrete data + brief reason if not Golden Dataset
Readiness
✓ Dependencies done or mocked · no blockers on story
✓ Integrations: target envs vs env for testing documented
✓ Known risks / open points listed (BA / PO) · not a blocker for QA start

Story scope (Entry Gate, BA/PO) ≠ QA test scope (Test design, QA) · Multi-release work: test automation expected from final release only

✕ Any gap → hard reject to BA/PO (no QA story points)
Keep this checklist visible when living the process · hard reject protects QA capacity Rail-Flow · QA

Quality layers & shared ownership

12 / 13

Quality is a team responsibility. Four layers in dev/test — then the pipeline runs the same way on every environment. Layers are enforced, not optional guidelines.

Process enforcement (Topic 2): Developer deploy rights on dev · test · acceptance are revoked — changes go through pull request only (100% compliance). No direct hotfixes on ACP; test-first path. Impacts current release prep but is required to stop mismatch and firefighting.
